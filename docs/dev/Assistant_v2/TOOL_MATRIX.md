## Reading conventions and scope

- Citations are repository-relative file:line or file:line–line. They refer to the snapshot above; architecture citations refer to the supplied, currently untracked contract file.
- **MISSING** means the named capability or required service/guard does not exist in the inspected code. A related route or helper is identified separately; it is not silently presented as a finished v2 tool.
- “No commit” and “no outbound” describe the cited function and its inspected call tree, not all work triggered by loading an arbitrary frontend page. “No outbound” includes no LLM, remote embedding, OCR or other HTTP call in that tree. Model downloads, local inference, API dispatch, telemetry and background jobs are distinguished below.
- Card text is the required meaning, not a newly implemented string. Existing behavior is cited from code; v2 requirements are cited from the contract. Read-only tools require no approval card (T0 catalog: docs/dev/ASSISTANT_V2_ARCHITECTURE.md:237–263). T2 cards must use server-resolved labels/resources, parameters, risk, revision and expiry; default expiry is 30 minutes and no always-allow option exists (docs/dev/ASSISTANT_V2_ARCHITECTURE.md:272–289). Deferred rows do not authorize any feature; missing behavior gets no invented confirmation.
- The requested output and notes paths take precedence over the architecture's other paths. See docs/dev/ASSISTANT_V2_NOTES.md. The task omits ask_user from its candidate list; it remains an architecture M3 item (docs/dev/ASSISTANT_V2_ARCHITECTURE.md:255), not an additional T1.1 row.

## 6. Required findings and contract contradictions

### 6.1 CvVersion family semantics and append

- A version ID identifies an immutable historical row; family_id is the first upload's ID, while internal version sequence increases across every CV owned by the student. Uniqueness is (owner_id, version), not family+major/minor (src/db/models.py:122–140). family_of falls back to id for old rows; versions_of explicitly filters owner/family and orders sequence descending (src/services/cv_versions.py:32–33, 47–55).
- Upload initializes a new family at v1.0; restore copies an older version into the same family at a new major .0; optimizer appends a minor version (src/services/cv_versions.py:67–83, 90–123; src/services/cv_optimizer.py:359). Listing shows one family head, while advisor CV grants cover every version (src/api/cv.py:82–92; src/services/advisor.py:579–584).
- append queries the current head for its label, sets family_id/sequence/major/minor and transfers active state from any active family member. It **does not commit**, check a caller identity, detect a changed base/head or protect filesystem effects (src/services/cv_versions.py:73–87). Thus appending from an old base currently succeeds with current-head numbering; it is not the stale-base protection required by the contract (docs/dev/ASSISTANT_V2_ARCHITECTURE.md:295).
- Startup backfill fills missing families/labels, moves active state to heads, relabels existing analyses and merges per-version CV share grants to family grants, with an internal commit (src/services/cv_versions.py:126–180; src/db/database.py:71–72).

### 6.2 Optimizer _load, review, finalize

- _load needs an **owned completed analysis** and an extant CV; absent/foreign analysis ->404, incomplete ->409, deleted CV ->409. It checks only CV existence after authorizing the analysis, not independent CV ownership. If no optimization exists it **creates and commits** a draft, even when reached by GET/session (src/services/cv_optimizer.py:154–176; src/api/optimizer.py:25–31). That side effect must not silently become a T0 proposal/read.
- Suggestions must correspond to an exact original line (line number, then text fallback). Each accept/edit/reject/undo updates draft decisions and appends CvEditAudit; edited text becomes one nonempty <=600-char line and cannot equal the original (src/services/cv_optimizer.py:93–104, 223–283). Capability answers require supplied experience context or optional learning note, are saved separately and not invented by a model (src/services/cv_optimizer.py:286–316).
- finalize checks draft status, applies only accepted/edited suggestion lines, carries developing skills separately, rejects no-change saves, appends a new minor version, builds a simple DOCX, writes it, then commits the new version and locked optimization; caught SQL failure removes the generated file (src/services/cv_optimizer.py:319–372; src/services/cv_files.py:109–139). It does not automatically re-score. A second finalize is a409; result_cv_version_id exists but no operation-id replay is implemented (src/services/cv_optimizer.py:179–185, 321–322; src/db/models.py:217–230).
- Grounding currently checks evidence presence, token overlap with the **whole CV**, and numeric set difference against the **whole CV** (src/services/guardrails.py:164–202). It does not preserve metric phrase/unit/noun per source bullet, check added entities/seniority, or revalidate edited text during finalize (src/services/cv_optimizer.py:247–263, 324–329). Proposal revisions, source-span hashes, changed-claim classifications, bound user assertions and comparable-score metadata are **MISSING** (src/db/models.py:183–253; contract docs/dev/ASSISTANT_V2_ARCHITECTURE.md:295–304).

### 6.3 Analysis commit, dispatch, failure and startup

- The analysis route does **not** commit itself. create_analysis commits the processing row (and any newly pasted JD) at src/services/gap_analysis.py:75; only after it returns does src/api/analysis.py:192 add the background task. A crash between those points leaves a committed row without dispatch.
- run_analysis reloads by analysis ID, reads raw CV/JD into graph state and streams every node; no queued->running CAS, prior-status check, duplicate claim, operation_id or open-analysis uniqueness exists (src/services/gap_analysis.py:118–179; src/db/models.py:183–206). Step/failure writes commit separately, completion commits result and extracted pasted-JD skills (src/services/gap_analysis.py:79–90, 145–153, 162–179).
- init_db calls fail_interrupted_analyses at startup; all processing rows become failed with a Vietnamese restart error and current_step=None, commit at src/db/seed.py:92. It does not set completed_at or machine error interrupted_by_restart, dispatch queued jobs, reconcile operations or resume waiting assistant runs (src/db/database.py:65–72; src/db/seed.py:81–92). This is an existing failure record, **not durable job execution**; FastAPI BackgroundTasks persistence is **MISSING**. Preserve existing processing responses while implementing future contract semantics (docs/dev/ASSISTANT_V2_ARCHITECTURE.md:58–65).
- Docker startup has no explicit workers=1 argument, compose has no pin, and lifespan/config contain no worker-count refusal (Dockerfile:34; docker-compose.yml:3–19; src/main.py:20–60; src/config.py:20–77). Default invocation must not be treated as the explicit deployment guard required by docs/dev/ASSISTANT_V2_ARCHITECTURE.md:63.

### 6.4 get_current_user today

- Identity is selected solely from client-controlled X-Demo-Role mapped to fixed seed user IDs; unknown/missing role or absent demo row ->401. No verified session, JWT or credential authentication exists in this dependency (src/api/deps.py:13–26; src/db/seed.py:12–13). Student/advisor guards check the resulting row's role, but cannot authenticate it (src/api/deps.py:32–47).
- Chat checks page role/user ID/routes against that selected user and overwrites context identity; conversation/turn checks scope legacy data by owner and role (src/api/assistant.py:54–66, 108–140). These are useful authorization checks, **not** satisfaction of verified-session identity in docs/dev/ASSISTANT_V2_ARCHITECTURE.md:29–32. The frontend intentionally sends X-Demo-Role (frontend/lib/assistant-api.ts:23–28).
- Advisor assignment and sharing checks generally exist in business services, but unauthorized assignment and unshared documents return403 rather than v2 resource-tool NOT_FOUND (src/services/advisor.py:71–80, 518–526, 573–582). Keep public API responses backward compatible; translate tool results separately (docs/dev/ASSISTANT_V2_ARCHITECTURE.md:3, 32).

### 6.5 Automatic tracing and privacy

- Settings default LangSmith tracing true, with project/endpoint; get_settings enables process LANGCHAIN_TRACING_V2/API_KEY/project/endpoint for a valid configured key. Its disable branch only covers absent-valid-key plus placeholder env key, not a general guaranteed tracing-off policy (src/config.py:47–54, 126–139).
- Lifespan sets LANGCHAIN_TRACING_V2=true whenever settings say tracing enabled; adds key/project/endpoint and prints status (src/main.py:24–38). No per-assistant/migrated-service tracing suppression occurs in their call paths (src/services/assistant/agent.py:289–331; src/services/gap_analysis.py:129–141). Actual environment configuration was not inspected; this documents enablement logic, not a claim that a production trace was observed.
- XML escaping of assistant input/history isolates prompt tags but is not masking. Raw messages/context/history are sent to the LLM; debug logging includes model thought (src/services/assistant/agent.py:287–313). Raw numbered CV text and raw JD text are also sent during scoring/extraction (src/agents/gap_analysis/nodes/compare_gap.py:23–31, 51–80; src/agents/gap_analysis/nodes/retrieve_context.py:28–32).
- invoke_json raises errors containing model output; analysis node logs those exceptions verbatim, potentially sending raw echoed text to logs (src/services/llm.py:114–117; src/agents/gap_analysis/nodes/retrieve_context.py:55–56; src/agents/gap_analysis/nodes/compare_gap.py:139–140). Grounding audit stores raw spans/rewrites/reasons in a separate data/audit_log.db and has no user/conversation fields (src/services/guardrails.py:10–11, 30–40, 63–79); its classification/access policy needs review under contract storage classes, not an assumption that it is masked telemetry (docs/dev/ASSISTANT_V2_ARCHITECTURE.md:132–140).
- Unified gateway, privacy vault/masking/egress scanner, usage-cost caps and production masking refusal are **MISSING** in current model factory and outbound functions (src/config.py:109–141; src/services/llm.py:110–121; src/services/jd_store.py:47–73; src/services/assistant/embedding.py:86–115). These contradict privacy requirements (docs/dev/ASSISTANT_V2_ARCHITECTURE.md:110–149), so future shipped tools cannot bypass T1.4 migration.

1. **Identity can be selected by client header.** Fixed demo-user mapping violates verified-session identity before any tool-side ownership check can establish the true caller (src/api/deps.py:13–26; contract docs/dev/ASSISTANT_V2_ARCHITECTURE.md:29–32).

Duplicate approval, crashes, cancellation and supersession cannot meet the contract as written (contract :44–78).
